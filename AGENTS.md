# Задачи агентов по дизайну

Результат задачи: отдельная ветка в этом репозитории с готовой версией дизайна и кратким описанием. Исходники сайта пока отсутствуют. Формат результата выбирайте по заданию пользователя: макеты, графика или код прототипа.

1. **Бриф:** определить аудиторию, цель страницы, контент и ограничения из задания пользователя. Неизвестное отмечать как допущение в README варианта.
2. **UX-агент:** подготовить структуру страницы, пользовательский путь и wireframe для desktop/mobile; описать навигацию и состояния.
3. **UI-агент:** разработать визуальное направление, компоненты, цвета, типографику и адаптивные макеты; приложить превью и исходники/ссылку на Figma.
4. **Агент по ассетам и передаче:** собрать оптимизированные изображения и SVG, источники и лицензии; описать размеры, отступы, состояния и адаптивное поведение.
5. **Проверка:** проверить читаемость, контраст, focus, согласованность компонентов и мобильную версию; записать результат в README варианта. Для кода указать команду запуска и выполнить доступные проверки.

Эти этапы может выполнить один агент; запуск отдельных агентов не требуется.

## Общие правила

- Прочитать README.md и docs/DESIGNERS.md, выполнить `git fetch origin`, создать уникальную ветку `design/<название-варианта>` от `origin/main`.
- Сохранить версию дизайна, сделать commit и `git push -u origin design/<название-варианта>`. Завершить ответом со ссылкой `https://github.com/Knyazzer/test-site/tree/design/<название-варианта>`.
- Не создавать fork, Issue, Pull Request, Azure-инфраструктуру, CI/CD или деплой в рамках передачи дизайна. Не пушить и не сливать изменения в `main`.
- Для push использовать существующую авторизацию GitHub с правом записи. Если доступа нет, сохранить локальный commit и сообщить, что нужен доступ; не заявлять об успешной загрузке.
- Соблюдать [инструкцию для дизайнеров](docs/DESIGNERS.md); материалы каждой задачи размещать в `design/submissions/<название-задачи>/`.
- Не менять и не удалять чужие материалы без согласованного задания.
- Не публиковать секреты, личные данные и материалы без права на публикацию.
- В README варианта кратко указать: что сделано, где превью, что проверено и какие вопросы остались. Не заявлять о проверках, которые не выполнялись.
