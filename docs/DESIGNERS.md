# Инструкция для дизайнеров

## Перед началом

Откройте Issue с задачей: какая страница нужна, для кого она, какое действие должен совершить пользователь и какие есть ограничения. Если бренд, тексты или структура ещё не согласованы, явно укажите свои допущения в описании макета.

## Что сдавать

- Ссылку на Figma с доступом на просмотр либо исходный файл в доступном формате.
- Превью основных экранов в PNG или WebP: desktop и mobile. Рекомендуемые ширины для передачи — 1440 и 390 px; это ориентиры, а не фиксированная ширина интерфейса.
- При необходимости — SVG-иконки, оптимизированные изображения, названия шрифтов и источники с условиями использования.
- Краткое описание сетки, отступов, типографики, цветов и поведения на промежуточных ширинах.
- Для интерактивных элементов — состояния hover, focus, active, disabled, loading, error и empty, где они применимы.

## Папки и имена

```text
design/submissions/<название-задачи>/
  README.md
  previews/
    home-desktop.png
    home-mobile.png
  assets/
    logo.svg
```

Используйте короткие имена латиницей через дефис. Названия экранов должны отражать страницу и размер. Большие исходники и видео передавайте ссылкой с понятными правами доступа. Не перезаписывайте чужие работы: используйте отдельную папку или согласованный PR.

## Проверка перед Pull Request

- У каждого экрана понятны цель, иерархия и основное действие.
- Мобильная версия учитывает длинный текст, меню и формы.
- Текст читается, контраст достаточен, элементы управления имеют видимый focus и удобную область нажатия.
- В README указаны ссылки, состояния, адаптивное поведение и нерешённые вопросы.
- Внешние ссылки открываются с тем уровнем доступа, который предусмотрен для участников проекта.
- Указаны источники и права на сторонние материалы.

В PR опишите изменения, приложите превью и свяжите задачу через `Closes #номер`. Если нужен промежуточный отзыв, откройте Draft PR. Решение о принятии принимает владелец репозитория.
