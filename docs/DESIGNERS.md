# Инструкция для дизайнеров

## Перед началом

Прочитайте задание пользователя и AGENTS.md. Создайте отдельную ветку `design/<название-варианта>` от актуальной `origin/main` по командам из README. Если бренд, тексты или структура ещё не согласованы, явно укажите свои допущения в описании дизайна.

## Что сдавать

- Исходники дизайна: макет, ссылку на Figma с доступом на просмотр или код прототипа, если это предусмотрено заданием. Для кода добавьте инструкцию запуска.
- Превью основных экранов в PNG или WebP: desktop и mobile. Рекомендуемые ширины для передачи — 1440 и 390 px; это ориентиры, а не фиксированная ширина интерфейса.
- При необходимости — SVG-иконки, оптимизированные изображения, названия шрифтов и источники с условиями использования.
- Краткое описание сетки, отступов, типографики, цветов и поведения на промежуточных ширинах.
- Для интерактивных элементов — состояния hover, focus, active, disabled, loading, error и empty, где они применимы.

## Папки и имена

```text
design/submissions/<название-задачи>/
  README.md
  previews/
    home-desktop.png
    home-mobile.png
  assets/
    logo.svg
```

Используйте короткие имена латиницей через дефис. Названия экранов должны отражать страницу и размер. Большие исходники и видео передавайте ссылкой с понятными правами доступа. Для своего варианта используйте отдельную папку и ветку; не перезаписывайте чужие работы.

## Проверка перед push

- У каждого экрана понятны цель, иерархия и основное действие.
- Мобильная версия учитывает длинный текст, меню и формы.
- Текст читается, контраст достаточен, элементы управления имеют видимый focus и удобную область нажатия.
- В README указаны ссылки, состояния, адаптивное поведение и нерешённые вопросы.
- Внешние ссылки открываются с тем уровнем доступа, который предусмотрен для участников проекта.
- Указаны источники и права на сторонние материалы.

Сделайте commit и push своей ветки в `Knyazzer/test-site`. Передайте пользователю ссылку на опубликованную ветку — это итог работы. Issue, fork, Pull Request и деплой не требуются. Не сливайте изменения в `main`.
